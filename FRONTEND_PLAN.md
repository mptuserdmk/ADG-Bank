## 1. Дизайн-система и визуальная концепция (Frontend-Design Standards)

В соответствии со скиллом `frontend-design`, банковский интерфейс ADG-Bank строится на принципах **сдержанности, типографики и архитектурной точности**:

### 1.1. Философия и эстетика
- **Анти-шаблонность (Zero AI Slop)**:
  - ❌ Никаких фиолетово-синих размытых градиентов и неоновых свечений.
  - ❌ Никаких смайликов вместо иконок (`🚀 ✨ 🎉`). Только строгие векторные пиктограммы с тонким штрихом (`stroke-width: 1.5px` от Lucide).
  - ❌ Никаких бесконечных скруглений (`rounded-full` на всем подряд). Радиус скруглений для карточек и инпутов — строгие `6px` / `8px`.
  - ❌ Никаких шаблонных пустых фраз: реальные цифры, реальные статусы, выверенные банковские формулировки.
- **Типографика**:
  - Основной шрифт: **Inter** / **Geist Sans** (чистый геометрический гротеск).
  - Числовые данные: моноширинные табличные цифры (`font-mono font-variant-numeric: tabular-nums`) для балансов, номеров счетов и сумм, чтобы числа не «прыгали» при обновлении.
- **Цветовая модель: «Один акцент, выверенные нейтрали»**:
  - Базовые нейтрали: глубокий графитовый/угольный фон или чистый бумажный (`#0A0A0A` / `#FAFAFA`).
  - Акцентный цвет: сдержанный изумрудный финтех-зеленый (`#10B981` / `#059669`) для подтверждений и акцентов, либо строгий кобальтовый синий (`#2563EB`).
  - Тонкие разделители (`--hairline: #262626` / `#E5E7EB`, 1px), разделяющие смысловые зоны без нагромождения теней.

### 1.2. Проработка состояний компонентов
Каждый компонент разрабатывается с учетом 6 состояний:
1. `Default` — спокойное базовое отображение.
2. `Hover` — деликатная подсветка подложки без резких скачков.
3. `Focus / Keyboard Focus` — четкое контрастное кольцо фокусировки (`focus-visible: ring-2`).
4. `Loading / Skeleton` — анатомические скелетоны, повторяющие форму данных вместо бессмысленных спиннеров посреди экрана.
5. `Empty State` — информативный экран с кнопкой действия (например, «У вас пока нет открытых счетов — открыть счет»).
6. `Degraded / Circuit Breaker Fallback` — визуальный баннер статуса при сбое зависимых микросервисов.

## 2. Архитектура и стек технологий

```
                           [ React 18 / 19 + TypeScript ]
                                         │
                 ┌───────────────────────┼───────────────────────┐
                 ▼                       ▼                       ▼
      [ TanStack Query v5 ]        [ React Router v6 ]      [ Tailwind CSS ]
   (кэш, мутации, поллинг)      (клиентские маршруты)    (дизайн-токены CSS)
                 │
                 ▼ (HTTP запросы с Idempotency-Key)
      [ Vite Dev Proxy / Axios ] ──► /api/** ──► Spring Cloud Gateway (:8080)
```

- **Сборщик**: **Vite 5+** (мгновенный запуск, строгий TypeScript, proxy-конфигурация).
- **Стилизация**: **Tailwind CSS** с кастомной дизайн-системой CSS-токенов (`--surface`, `--ink`, `--hairline`, `--accent`).
- **Иконки**: **Lucide React** (лаконичные пиктограммы с настраиваемой толщиной линий).
- **Управление состоянием и сетевой слой**:
  - **TanStack Query (React Query v5)**: кэширование балансов, автоматическая инвалидация данных после перевода, обработка сетевых ошибок.
  - **Axios** с настроенными перехватчиками (Interceptors): автоматическая подстановка заголовка `X-Idempotency-Key` (UUIDv4) для всех мутирующих запросов (POST/PUT).
- **Валидация форм**: **React Hook Form** + **Zod** (валидация сумм, корректности счета, лимитов).

## 3. Структура экранов интерфейса (Information Architecture)

### 3.1. Каркас приложения (`App Chrome` / `Sidebar`)
- Лаконичный левый сайдбар (Linear style):
  - Логотип **ADG-Bank** и бейдж окружения (`Demo / Local`).
  - Быстрый переключатель активного тестового пользователя (`Current User Selector`).
  - Основная навигация:
    - `Обзор (Dashboard)` (`/`)
    - `Счета (Accounts)` (`/accounts`)
    - `Переводы (Transfers)` (`/transfers`)
    - `История операций` (`/transactions`)
    - `Статус системы (System Health)` (`/system`)
  - Подвал сайдбара: индикатор доступности шлюза и микросервисов (зеленый/желтый/красный пульсирующий индикатор).

### 3.2. Экран 1: Главная панель (`Dashboard` — `/`)
- **Блок общего баланса**: общая сумма активов с моноширинным форматированием (`1 250 450.00 ₽`), процент изменения.
- **Быстрые счета**: горизонтальный скролл или сетка компактных карточек счетов (номер счета маскирован: `•••• 4821`, баланс, валюта).
- **Кнопка быстрого действия**: «Новый перевод» с хоткеем (`Cmd+K` / `Ctrl+K` или прямой клик).
- **Последние транзакции**: компактная таблица с иконками направления (зеленая стрелка входящего, графитовая исходящего), суммами и бейджами статуса (`SUCCESS`, `PENDING`, `FALLBACK`).

### 3.3. Экран 2: Управление счетами (`Accounts` — `/accounts`)
- Список всех счетов выбранного пользователя.
- Детализация по клику на счет:
  - Полный номер счета (с кнопкой копирования в буфер обмена).
  - Текущий баланс и заблокированные средства.
  - Персональная выписка по счету.
- Модальное окно / Drawer: «Открытие нового счета» (выбор валюты: RUB / USD / EUR, начальный депозит).

### 3.4. Экран 3: Денежные переводы (`Transfers` — `/transfers`)
- Карточка формы перевода:
  1. **Счет списания**: выпадающий список доступных счетов с отображением текущего баланса.
  2. **Счет зачисления**: ввод номера целевого счета (с моментальной проверкой существования).
  3. **Сумма перевода**: инпут с крупными цифрами, валидацией остатка (нельзя отправить больше баланса) и быстрыми кнопками (1 000, 5 000, 10 000, «Весь остаток»).
  4. **Назначение платежа**: опциональный комментарий.
- **Отработка надежности и Circuit Breaker**:
  - При отправке генерируется `idempotencyKey = crypto.randomUUID()`.
  - Если `account-service` работает штатно: мгновенное списание, анимация успеха, обновление балансов через `queryClient.invalidateQueries`.
  - **Если сработал Circuit Breaker**: всплывает информативный янтарно-желтый баннер:
    > *«⚠️ Сервис проведения транзакций работает в режиме защиты (Circuit Breaker OPEN). Операция отложена или принята резервным шлюзом. Ваши средства в безопасности.»*

### 3.5. Экран 4: Мониторинг микросервисов (`System Status` — `/system`)
Специальный экран для демонстрации учебного проекта:
- Опрос Actuator эндпоинтов микросервисов через Gateway.
- Карточки каждого микросервиса:
  - `Config Server` (8888) — статус `UP`.
  - `Eureka Discovery` (8761) — зарегистрированные инстансы.
  - `User Service` (8081) — статус `UP`.
  - `Account Service` (8082) — статус `UP` / `DOWN`.
  - `Transaction Service` (8083) — состояние Circuit Breaker (`CLOSED`, `OPEN`, `HALF_OPEN`), процент ошибок.

## 4. Пошаговый план реализации фронтенда

### Этап 1: Инициализация и настройка проекта (`frontend/`)
- [ ] Развернуть проект с помощью Vite:
  ```powershell
  npm create vite@latest frontend -- --template react-ts
  ```
- [ ] Установить ключевые библиотеки:
  ```powershell
  cd frontend
  npm install @tanstack/react-query lucide-react react-router-dom axios clsx tailwind-merge zod react-hook-form @hookform/resolvers
  npm install -D tailwindcss postcss autoprefixer
  npx tailwindcss init -p
  ```
- [ ] Настроить Vite Dev Server Proxy в `vite.config.ts`:
  - Маршруты `/api` проксируются на `http://localhost:8080` (Spring Cloud Gateway).
- [ ] Настроить CSS-токены дизайн-системы (палитра, шрифты, границы) в `src/index.css`.

### Этап 2: Сетевой слой и интеграция с API Gateway
- [ ] Создать `src/api/client.ts`:
  - Базовый экземпляр Axios с таймаутами и перехватчиками.
  - Автоматическая подстановка `X-Idempotency-Key` для POST-запросов.
  - Единая типизированная обработка ошибок `ApiErrorResponse`.
- [ ] Создать API-модули:
  - `usersApi.ts`: `getUsers()`, `getUserById(id)`, `createUser(...)`.
  - `accountsApi.ts`: `getAccounts(userId)`, `getAccountById(id)`, `createAccount(...)`.
  - `transactionsApi.ts`: `transfer(...)`, `getTransactionHistory(accountId)`.
  - `systemApi.ts`: опрос `/actuator/health` микросервисов.

### Этап 3: Базовые UI-компоненты (Design System Components)
- [ ] `Button`: варианты `primary`, `secondary`, `danger`, `ghost`, состояния `isLoading` с сохранением ширины.
- [ ] `Input` & `AmountInput`: табличные цифры, префикс валюты, понятные тексты валидации.
- [ ] `Card` & `HairlineCard`: контейнеры с 1px границей `--hairline` без лишних теней.
- [ ] `Badge` / `StatusPill`: статусы транзакций (`Success` — неяркий зеленый, `Pending` — желтый, `Failed` — красный, `Fallback` — фиолетовый/янтарный).
- [ ] `Skeleton`: анатомические заглушки для карточек счетов и строк выписки.
- [ ] `Banner`: информационные уведомления и предупреждения Circuit Breaker.

### Этап 4: Разработка каркаса (Layout) и навигации
- [ ] Реализовать `AppLayout` с сайдбаром в стиле Linear (`Sidebar`, `NavItem`, `UserSwitcher`).

- [ ] Добавить глобальный контекст активного пользователя (`UserContext`), чтобы можно было переключаться между клиентами банка в один клик.

### Этап 5: Разработка бизнес-экранов

## 5. Чек-лист соответствия качеству (`frontend-design` audit)

- [ ] **Цвет**: не более одного главного акцента, нейтрали выдержаны в единой цветовой температуре.
- [ ] **Цифры**: все балансы отрендерены шрифтом с табличными моноширинными цифрами (`tabular-nums`).
- [ ] **Скелетоны**: во время загрузки нет мерцающих пустых белых пятен или гигантских спиннеров.
- [ ] **Ошибки**: текст ошибок на человеческом языке без сырых стектрейсов Java (`NullPointerException` и т.п.).
- [ ] **Надежность**: ни один повторный клик по кнопке «Перевести» не может отправить два запроса с одинаковым ключом идемпотентности.
